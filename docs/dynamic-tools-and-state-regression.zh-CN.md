# 动态工具与属性系统：修复和模拟回归

## 本次解决的问题

本次从主线 `f82a5c33e7ee3febb32ade3e82c53fc3a4c8ca11` 开始。LLM 继续自行选择行动；后端负责提供当前有效的菜单、校验意图和结算结果。无效模型回复仍走原有协议修复流程。

| 环节 | 原问题 | 修复后的约束 |
|---|---|---|
| 工具发现与校验 | 禁用模块仍能直接调用；外部工具串入其他世界 | `WorldToolPolicy` 统一世界模块和外部工具集规则 |
| 工具热更新 | 只新增，不更新或移除旧定义 | 同步有效外部定义快照，保护内置工具；整体读取抛异常时保留旧注册表，单个无效包按原加载器规则跳过并记录错误 |
| 菜单目标 | A/B 临时编号重排后，旧行动可能选错居民 | 参数携带稳定居民 ID；询问姓名与关系意图转换保留该 ID，执行时重新确认同世界、当前可见及目标条件 |
| 姓名与介绍 | 重名查询异常或猜测对象，第三者介绍缺少准确绑定 | 已知姓名与 ID 同时匹配；重名明确报歧义，介绍分别绑定接收者和第三者 |
| 认知隔离 | 重名区分可能显示尚未认识的外貌 | 只显示角色已记录的外貌；未见过的对象使用“外貌未记录”和编号 |
| 参数边界 | 空地点、部分字符串、畸形数字和非文字台词被误接受 | 精确地点匹配；类型及有限数值校验；目标编号必须完整匹配已展示候选 |
| 菜单容量 | 分类配额打乱紧急需求排序，日记/休息被挤出 | 先保留需求和基础行动，再保持原有优先级顺序；不替模型代选 |
| 行动重选 | 菜单继续展示被连续重复规则拒绝的行动，空回合可永久停滞 | 选择与修复菜单共用重复门槛，单次查询历史后过滤，保留原编号与生存行动豁免 |
| 执行事务 | 处理器异常留下部分属性、时钟或事件 | 每次执行用保存点隔离异常，成功仍属于调用者外层事务 |
| 失败反馈 | 下游拒绝、失眠、市场或世界观行动失败仍获成功奖励 | 明确区分未完成行动和已实施的世界内尝试，拒绝项不发成功学习奖励 |
| 调度 | 逐项提交时世界时钟倒退；子会话看不到准备写入 | 检查和执行使用同一批次起点，提交时保存最远结束时间；准备写入先提交，执行前刷新父会话 |
| 属性变化 | delta 能修改 ORM 时钟；NaN/Infinity 污染属性 | 动态字段白名单，完整检查后写入，恢复合法范围并同步衍生需求 |
| 属性读取 | 查钱包会迁移并写回整份角色状态 | 钱包与驱动力读取不改写角色；初始化仅在值变化时赋值 |
| 目录动作效果 | `create`、`treat` 等名称误命中 `eat`，写作、治疗或食物话题被当成进食 | 按实际动作的结构化名称及精确动作名分类，事件描述与属性结算共用分类结果 |
| 属性演化 | 跨零时间、大步睡眠与小步推进不一致 | 插值记录真实跨零分钟，按睡眠/昏迷/清醒窗口分段演化 |
| 公共卫生 | 每名居民各衰减一次地点，居民越多环境越快变脏 | 地点共享时钟，按累计暴露积分计算个人影响 |
| 长期生存 | 昏迷分支推迟已经成立的致死条件 | 致死条件先于疲劳昏迷检查；死后重复调用不再衰减、恢复或重复记录死亡 |
| 世界观效果 | 负成本套利、零权重被抽中、分支实际费用未复查 | 预检内容数值，所选 outcome 重新核对真实费用，零权重不参加抽签 |
| 世界观升级 | 大量经验逐级循环可能卡住 | 累计等级成本加二分查找，保持原曲线结果，清除过期升级提示 |

### 长程模拟实际发现的问题

失眠原先不消耗世界时间，随机结果又由同一时刻的种子决定，因此重复选择会始终失败。现在失眠尝试消耗基础 15 分钟（经过世界时间倍率），同一居民自失败尝试开始起等待 30 分钟后才能再次尝试。冷却期的休息、移动和其他选择仍由模型决定。成功睡眠保持实际时间窗口；立即叫醒按 0 分钟结算，晚唤醒只计算原定结束前的睡眠，重复完成不再重复扣罚或生成梦回顾。

首轮 400 回合的逐人模式样本还显示，社区援助经常出现在尚未冷却的菜单中。现在菜单与执行共用 `community_aid_wait_minutes`，包括时间戳为 0 和恰好到达冷却边界的情况。额度、补给量及各难度原有冷却时长保持原规则。

继续复跑后，批次模式种子 7 在第 314 回合、逐人模式种子 97 在第 351 回合触发了连续 10 回合无时间推进的断言。保存的末尾状态显示：其他居民都在睡眠，唯一清醒居民刚连续移动两次。模型从菜单选一个补给目的地，被后置重复规则拒绝；修复时换另一个目的地，仍然属于移动，也被拒绝。由于没有执行产生新事件，这个循环无法自行消失。现在普通选择和修复都先移除当前必被重复规则拒绝的选项。原来的限制阈值和生存豁免不变，模型仍自行选择剩余行动；最小回归直接复现“喝完最后一瓶水、连续移动两次、再次寻找补给”的真实调度路径。

检查上述失败场景的真实事件还发现，`tool_create_write_diary` 被描述成吃饭并增加饱腹值。原来的宽泛子串规则把 `create`、`treat`、`heat` 中的 `eat`，以及 `arrest` 中的 `rest` 都认成了生理动作；分类和摘要提到食物或睡眠也会触发同类误判。现在只根据实际动作名称分类。日记、诗和绘画仍消耗原定时间，但不再凭空补充食物；给孩子水、请求食物、洗碗、整理床铺等也不再被当成自己吃喝或睡觉。真正吃饭、喝水与休息的原有效果和价格由实际执行回归验证。

## 如何复现

在项目根目录安装锁定依赖并运行：

```bash
uv sync --frozen
uv run pytest backend/app/tests -q
npm --prefix frontend ci --ignore-scripts
npm --prefix frontend run build
```

离线长模拟：

```bash
uv run python scripts/simulate_regression.py --modes batch --seeds 7 83 --rounds 400 --output /tmp/tinyworld-batch.json
uv run python scripts/simulate_regression.py --modes per_agent --seeds 29 97 --rounds 400 --output /tmp/tinyworld-per-agent.json
uv run python scripts/simulate_regression.py --modes parallel --seeds 101 211 --rounds 400 --output /tmp/tinyworld-parallel.json
```

每个场景默认 4 名居民，从第 1 天 08:00 开始，初始资金分别为 0、20、80、250，并各持有有限的食物和饮水。种子影响人格初值、移动、闲暇活动和说话目标。默认每 17 次提供者调用注入一次不符合协议的回复，随后通过真实修复路径继续。

脚本使用临时数据库和配置，不需要供应商密钥。它实际运行菜单生成、AOHP 解析、工具校验、效果、时间推进、日常经济、调度及 SQLite 提交；文本提供者和 WebSocket 传输使用确定性替身。每回合使用新 Session 检查存储结果，广播时还从独立 Session 观察已经提交的世界时间。

报告分别记录 `action_attempts`、`provider_calls`、`protocol_faults`、`repair_calls`、每个工具的失败次数及失败原因。动作尝试数与提供者调用次数并不等同；后者还包含协议修复和行动重选。状态、库存、关系或世界引用违反不变量，以及已提交时钟回退或本场景持续停滞，都会带着种子、模式和回合数报错并非零退出。使用 `--output` 时，失败诊断还会保存最近选择、居民状态和末尾事件的必要字段；不包含供应商配置、密钥或完整提示词。所有居民死亡等明确终止状态正常结束，报告实际完成的 `rounds` 与 `terminal_status`。

- 六场独立长跑全部达到 `round_limit`，各完成 400 回合。

合计 2,400 回合、5,952 次真实工具执行尝试、6,322 次文本提供者调用。每场 4 名居民均存活，所有属性、库存、关系、世界引用和持久化不变量通过。已提交世界时钟回退为 0，最长连续未推进时间仅 1 回合，没有触发持续停滞门槛。援助 97 次选择均成功，`tool_failed` 事件为 0。

执行结果中另有 108 次真实规则下的失眠失败，均有时间消耗并能够继续运行；不能将这些正常的随机失败算成成功动作。共注入 367 次协议错误，记录 369 次修复调用，包含协议修复及行动重选。批次种子 7、逐人种子 97 的两个已复现停滞场景均在原策略下完成最终长跑。

属性长程测试另外推进了 12,000 小时（500 天），按预定补给与活动检查数值和衍生需求。4 种难度下，含/不含跨边界睡眠窗口的同一 3 天区间，分别以 1 分钟、7 分钟、60 分钟和一次 3 天推进；确定性生理属性在 `1e-8` 内一致，零值起点一致。还包含 100 次公共环境变动、无人照料直至死亡与死后重复检查、300 组等级曲线随机对照及巨量经验输入。

这些覆盖由以下测试维护：

- `test_dynamic_tool_invariants.py`：模块开关、外部工具隔离与刷新、临时目标和重名、意图转换全链路的目标稳定性、参数与菜单边界。
- `test_attribute_invariants.py`：数值合法性、只读状态、属性演化、公共环境、死亡、声明式世界观效果及目录动作误分类。
- `test_execution_integrity.py`：执行事务、外层回滚、跨世界隔离、失败奖励、组合效果和真实睡眠时长。
- `test_long_run_simulation.py`：三种调度模式、多天持久化、同种子独立数据库重放、过期目标、耗尽库存、失败重试、真实失眠、援助冷却和重复移动停滞。

## 范围与后续合并

离线模拟检验的是后端一致性和指定行动策略下的持续运行，不能据此判断真实 LLM 的决策质量、叙事质量或供应商网络并发性能。SQLite 的 `parallel` 设置沿用当前主线的逐个请求行为；真正并发请求由已有 [PR #6](https://github.com/3121455692atou-sudo/TinyWorld/pull/6) 单独处理。

稳定目标保证针对已携带 ID 的菜单行动：原目标仍可见时继续使用原 ID，原目标离场则拒绝。兼容的旧式直接调用如果只传 `visible_ref`，仍按调用时的当前编号解析；经过显式称呼解析的意图转换会补充稳定 ID。

合并 PR #6 时应保留其 `TaskGroup`、每次网络等待前释放写事务与取消清理，同时保留本次动态 `database.SessionLocal`、跨世界保护、重试去重和提交最大时钟。其测试中对旧 `runner_module.SessionLocal` 的 monkeypatch 需要随动态绑定调整。

时间分段等价性覆盖确定性生理衰减与环境暴露；本次没有把随机事件和原有周期性非致死伤害改成全历史追算。环境累计游标保留正常运行的历史暴露，地点历史最多保留 64 段；首次恢复的旧居民若早于可用历史，只能使用最早可用锚点。`go_eat_food` / `go_drink_water` 的候选可达性可作为后续单独改进评估。
